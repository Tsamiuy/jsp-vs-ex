# Changelog

What changed in each version, newest first. Each version has two parts: **For players** is the release notes in plain words, and **Technical changes** is the full record. Versions are `X.Y.Z` (`installer/VERSION`); 0.1.0 to 0.6.1 are pre-releases, and the first full release will be 1.0.0. The technical part follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). How to write an entry, with a template: `CONTRIBUTING.md`.

## [Unreleased]

### For players

**New**

- **Two-page Main Menu.** The Main Menu now shows five rows: Battle Modes, J-Customize, J-Point Shop, Gallery and Options. Battle Modes opens a second page with the game's battle rows (J-Adventure, Victory Road, Arcade, Free Battle, Online Battle) and two new rows: Training Mode, which starts a Free Battle with Training on, and Impossible Mode, which starts the Impossible 2 vs 1 fight. The row names are drawn by the port in the look of the game's own labels, and the help line and the button bar change with the page. It is on for everyone; the technical notes say how to switch it off and get the game's own menu back. Tried in scripted runs on one Windows PC with a keyboard; not tried online or with a second pad.
- **3v3 in Free Battle.** In Free Battle, a window on the 1 Player / 2 Players list asks for 2 vs 2 or 3 vs 3. A 3 vs 3 gives each team a third fighter on the Character Select (with a layout of its own), the Stage Select and the VS screen show three fighters per team, and the fight has six fighters. It works with 2 Players (Player 2 joins with Start). The other modes stay 2 vs 2. It is on for everyone together with the two-page Main Menu; the technical notes say how to switch it off. Tried in scripted runs on one Windows PC; "Fight again" and "Re-select" after a 3 vs 3 match and online play are not tried.
- **A box in the settings window for the new Main Menu.** On the Display tab, "Two-page Main Menu and 3v3" is ticked. Unticking it gives the game's own Main Menu back (and no 3v3). The window itself has not been seen on Windows yet.
- **Rollback matches stay in step (experimental, opt-in).** The rollback netcode that two players can turn on for a 2 vs 2 match was reworked so both PCs keep simulating the same fight: sound, the game clock and helper threads now follow the game tick, a match that freezes on one PC ends on both, the KO and time-up end is confirmed on both PCs, and the input delay adapts to the connection. A 3 vs 3 fight is refused with a message (rollback is 2 vs 2 only). Not tried in a game run in this form; only checked with the automated tests.
- **The installer can add the re-psn desktop app (optional, unticked, pre-release).** A new box on the tasks page, "re-psn desktop app (pre-release): play first, host if it works for you", copies the re-psn v0.9.0 desktop app into its own folder beside the game. The app is partial and in progress; it is unsigned, so Windows SmartScreen may warn; hosting from it on native Windows is not verified (tested only under Wine); there is no public server and no accounts, each host is a private server for friends; and the game connects without it. Setup only copies it: nothing is started and no firewall rule is added. Known limit: v0.9.0 lacks re-psn's member-ID wrap fix (re-psn #248). The app is fetched when the installer is built, checked against its pinned SHA-256 and the release's SHA256SUMS; the zip is not in this repository and your install downloads nothing. Not in the portable zip. The app opens in your web browser; its own window program (`re-psn-window.exe`) is left out of this setup and comes in a later version. The release archive has no licence texts for the Go modules built into the app, so the setup adds a THIRD-PARTY-LICENSES.txt to the app's folder (each text pinned by SHA-256 and fetched when the installer is built), and NOTICE.md lists every module, version and copyright line. Only checked with the automated tests; the setup with the box has not been built or run yet.
- **A button for the re-psn desktop app.** When the re-psn desktop app was ticked in the installer, the settings window's Online tab has an "Open the re-psn app" button under the "Save online settings" row, with the app's caveats in grey (pre-release and partial; unsigned, so SmartScreen may warn; hosting on native Windows not verified, tested only under Wine; no public server and no accounts; the game connects without the app; it opens in your web browser). It starts the app with `ui --browser` and does not wait for it (it needs only `re-psn-app.exe` and `re-psn-host.exe`); the launcher passes it nothing else. If the app folder is incomplete, the button is greyed out and says to reinstall with the option ticked. Only checked with the automated tests; not clicked on Windows yet.
- **Training Mode: a new menu and more options.** Start in a Training fight opens a menu of two windows. CPU Settings: CPU Level (0 to 5 stars, live) and CPU Behavior (Stand, Guard, Jump, Attack, Fights back). System Settings: Unlimited Stamina, Support cooldown off and Infinite Victory Burst. Position Reset: start spots, close together, bring the CPU to the player, save and go back to the saved spots. Camera / HUD: Free Camera and Hide HUD. Plus Skill Table, Re-select Characters and Return to Main Menu. In the fight, Select with Cross, Circle, Triangle, R1 or Square does the position actions, and a line along the bottom of the picture shows the keys with the game's own button pictures. Training no longer plays the fighter intros, and with 2 Players the two partner slots stay free. Tried in scripted runs on one Windows PC with a test pad for Player 2; a real second controller is not tried. The technical notes list the switches that turn each part off.
- **Arcade for 2 Players.** Choosing Arcade opens a window that asks 1 Player or 2 Players. With 2 Players, Player 2 picks the partner on the Character Select and plays it in split screen, both on the same team. Tried in scripted runs on one Windows PC with a test pad for Player 2: the window, Player 2's pick and a split-screen fight; a real second controller and the later Arcade fights are not tried.
- **Model Viewer on the Character Select.** On the 1 Player Character Select of Victory Road, Arcade, Free Battle, Training and Impossible, the Gallery's model viewer now stands where the character grid was. Left and Right go through the fighters (the Supports on a Support slot), the right stick turns the model, and the name is shown in the game's own name picture. It is not used on the 2 Players Character Select, in 3 vs 3 or online, where the grid stays. Tried in scripted runs on one Windows PC; the technical notes say how to switch it off.
- **Training Mode: a new menu and more options.** Start in a Training fight opens a menu of two windows. CPU Settings: CPU Level (0 to 5 stars, live) and CPU Behavior (Stand, Guard, Jump, Attack, Fights back). System Settings: Unlimited Stamina, Support cooldown off and Infinite Victory Burst. Tried in scripted runs on one Windows PC with a test pad for Player 2; a real second controller is not tried. The technical notes list the switches that turn each part off.
- **Sharpening and Texture filtering.** Two new settings in the Graphics group: Sharpening (Off, 25, 50, 75 or 100 percent) makes the fight picture crisper without touching the HUD, text or menus, and Texture filtering (the game's own, 2x, 4x, 8x or 16x) makes floors and walls seen at a flat angle clearer. They are rows on the Options page's Graphics list and two boxes under Edge smoothing in the settings window, which starts with 16x and 50; a game with no value set uses its own filtering and no sharpening. Both apply at the next start. Tried in scripted runs on one Windows PC at 720p; the settings window was compiled but not opened on Windows yet; not tried at 4K or on the EU and JP discs.

**Changed**

- **2 Players split screen runs faster.** A 2 Players 2 vs 2 fight on a busy stage ran at about 18 to 24 frames per second on one Windows PC and now runs at about 28 to 30 with the default settings; 1 Player is the same as before. It uses 16 MB more graphics upload memory. Measured on one PC only.
- **Support bundles name the version.** The zip from "Make a support bundle" is now called `jsp-support-<version>-<time>.zip`, so a bug report shows which version it came from at a glance. If the version file next to the game is missing, the name stays `jsp-support-<time>.zip`. Tried with the host test only; not tried on Windows yet.
- **Mods follow one standard.** [MODS.md](docs/MODS.md) now has a "Mod package standard": how a mod zip is laid out, every field of `mod.json`, gameplay or cosmetic and what that means online, the disc a mod is for, marking content that comes from the game or from someone else, and a checklist to run before sharing a mod. It also describes a planned way to get a match's mods online, which is not built.

**Fixed**

- **Port overlay pictures no longer flicker back.** A picture the port draws over the game and changes every frame (an animation) could show an older picture for a frame or two instead of the new one. It now waits for the new picture. Seen in test runs on one Windows PC only.
- **KO sound no longer repeats with 4 or 5 KOs to win.** In a Free Battle with "KOs to win" set to 4 or 5, the sound of the KO bar (the "one KO left" sound) could play over and over for the rest of the match. It now plays once for each KO. Tried in test fights on one Windows PC; not tried online.
- **Online Battle no longer stays on "Communicating..." after a lost opponent.** When the other player quit in the middle of a fight ("Connection has timed out.", OK), the next Online Battle sat on "Communicating..." for good. The port now ends the old connection's wait the way a PS3 does, so the game can go on. Not seen in a game yet: checked only by a test program on Linux.
- **The Impossible CPU's stars are orange-red on the 2 Players Character Select.** In an Impossible fight with 2 Players the five stars of the Impossible CPU stayed yellow, on its box and in the settings window. They now get the same colour as on the 1 Player screen. Tried on one Windows PC with a test pad.
- **The third fighter's icon follows the Fight HUD size in 3 vs 3.** At a smaller Fight HUD size the third fighter's face icon in the player block kept its full size. It now scales with the rest. Tried in a 3 vs 3 fight at Fight HUD size 50 %.
- **The title screen's demo fight no longer freezes on its loading screen.** Left alone at the title screen, the demo fight could stop on its loading screen about a minute in. It was being set up as a 3 vs 3 before the main menu had been seen; it now starts as 2 vs 2 until a size is chosen. Tried in scripted runs of the title demo on one Windows PC.
- **The EU disc builds again.** First-time setup with the EU disc (BLES02136) stopped with compile errors since the last features came in. It builds again. On the EU disc the port now leaves the game as on the console, apart from the PC wording of the save messages: these features are US disc (BLUS31519) only for now and are off on the EU disc: the two-page Main Menu, 3v3, the Model Viewer, Training Mode with its menu and options, Impossible Mode, Arcade for 2 Players, the Port Settings page and version line, Exit Game, menu mouse and d-pad jump, Fight HUD size, edge smoothing, sharpening, shadow distance, model detail, object draw distance, the FPS counter, Unlock everything, rollback netcode, and mods that add fighters (roster, card_as) or loose files. On the EU disc the log has a "not available on this disc yet" line for each one that is on by default or switched on, and such a mod is refused with that reason; the settings window marks them as US disc only. Online with the game's own online, and everything on the US disc, is unchanged. Run in the game on 2026-11-25 under Proton on one PC with the EU disc in English, exe built from this change before its last review fixes (log wording and launcher captions): the title, the game's own save dialog and the one-page Main Menu with the right help line, no crash, and a "not available on this disc yet" line for each feature on by default. Not run: the other EU languages, a fight on the EU disc. (`jsp_region.h`; CI now compiles the port for the EU disc too: `tools/ci/port_syntax_check.py`, `tools/ci/eu_lift_funcs.txt`)

### Technical changes

#### Added

- **Mod verification (maintainer tooling, nothing in the game changes).** An issue form `mod_verification.yml` asks for a mod's id, name, version, author, download link, `mod.json`, kind of change, game version and a rights confirmation. When a maintainer adds the label `mod-check`, `.github/workflows/mod-verify.yml` runs `tools/ci/mod_verify.py` (standard library only): it downloads the HTTPS link (size cap 200 MB, stops after about 280 s in all (if it stops early the comment says so and nothing is verified), each address resolved once and connected to by that address, no redirect to a non-HTTPS or non-public address), reads the zip without unpacking it (no `..`, absolute path, link, encrypted entry, device name or case clash; caps on entries and unpacked size), refuses executables, scripts and port source, checks `mod.json` against schema 1 (a Python copy of `parse_manifest` in `jsp_mods_core.h`), computes the canonical mod hash (`jsp-mod-hash 1`, specified in `docs/MODS.md`) and posts one comment. The workflow has two jobs (the check with `contents: read` only, the comment with `issues: write` only), no secrets and no checkout of the mod; `--zip FILE` checks a zip on the maintainer's PC. The form asks the author to confirm the mod is their own work, and each tested-list entry has `content: "own-work"`. `mods/tested.json` is the list of mods a maintainer has played, starting empty; `tools/ci/check_tested_mods.py` checks it in CI. Tested: host test `tools/ci/test_mod_verify.py`, actionlint on the workflow. Not tested: a real GitHub run, a download from a real host.
- **Rollback netcode core (EXPERIMENTAL, opt-in `JSP_ROLLBACK=1`), split from #248.** The GekkoNet additions (final frame, round-trip count, last acked frame), the stepper's lockstep frame clock with its stall rule (`jsp_stall_rule.h`: lost-flip write-off, 60 s failure, 5 s release), the snapshot ring changes, the fight hash with the battle setup table rule (`jsp_fight_setup_rule.h`), the KO / time-up end rule (`jsp_net_ko_rule.h`), adaptive input delay (`jsp_net_delay_rule.h`), the determinism locks (audio tick lock 3005, guest clock shift 3006, the sound-server lock, helper thread registers 7923; the toolkit patches are the line below), the rollback bench and replays (test tooling), and the F9 hold to end a match. Changes in this split: a frame clock failure ends the session through its keepalive worker (`jsp_host_abort.h`; the session's accessors are locked), the test switches `JSP_NET_LINK`, `JSP_AUDIO_TICKLOCK`, `JSP_NET_CRI_LOCK`, `JSP_NET_GUEST_CLOCK`, `JSP_NET_THREAD_REGS`, `JSP_ROLLBACK_LIMITED_SAVING`, `JSP_ROLLBACK_START`, `JSP_ROLLBACK_INPUTS` and `JSP_ROLLBACK_INPUTS_SKIP`, and the fight hash switches `JSP_FIGHT_HASH_RNG_PTRS`, `JSP_FIGHT_HASH_SCENE`, `JSP_FIGHT_HASH_CAM_CACHE` and `JSP_FIGHT_HASH_FIGHTER`, apply only with `JSP_ROLLBACK_ALLOW_DEBUG=1` (`jsp_net_debug_gate.h`; the launcher passes every `play_settings.txt` line to the game, so the gate stops a stray line, not a deliberate debug setup), a 3 vs 3 fight is refused at the session start (`jsp_net_team_rule.h`), the session layer documents its thread contract, and the round trip under the fight timer is left to an optional UI module (three weak hooks; this build draws nothing there). Tested: host tests (`net_session_test.sh`, `net_repsn_test.sh`, `net_online_test.sh`, `host_abort_test.sh`, `net_debug_gate_test.sh`, `net_team_rule_test.sh`, `stall_rule_test.sh`, `thread_audit_test.sh`, `net_delay_rule_test.sh`, `fight_setup_rule_test.sh`, `snapshot_ring_test.sh`, `net_badge_test.sh`), the toolkit export and the port syntax check. Not tested: any game run of this split (no single-PC, two-copy or two-PC match), Windows, 3 vs 3 refusal on screen. (#248)
- **Toolkit patches for the rollback netcode (EXPERIMENTAL), split from #248.** Eight new toolkit patches and one changed: 3005 (`cellAudio` tick-locked mode, `g_ps3_audio_lock_target`), 3006 (a per-thread shift of the guest timebase and `sys_time_get_system_time`, `g_ps3_guest_tb_shift`, and a `sys_timer_usleep` hook), 7915 (changed: `cellPad.h` declares the two pad hooks, and the info hook's comment says what it sees), 7919 (`g_rsx_skip_draws`: skip the draws of re-run frames), 7920 (`g_vm_layout_gen`, the guest memory layout generation), 7921 (the lwmutex census walks the occupied slots and caches readability per page), 7922 (`ps3_pad_peek_record`), 7923 (`ps3_ppu_thread_ctx`) and 7927 (`cellGcm_flip_write_off_lost`: write off a queued flip the FIFO walker can never reach), with their `INDEX.md` rows. Each is off or unused until the rollback netcode core (the next pull request) sets or calls it; what runs without it is one atomic increment per guest memory commit or protection change (7920), the lwmutex table's list of occupied slots (7921), one more event object when the audio mixer starts (3005), and 7927's test switch `GCM_TEST_LOSE_FLIP`, read once. From #248 by jamesdwise45-spec. Tested: the 150 toolkit patches export (`export_toolkit.py`), also with `core.autocrlf` true; the port syntax check passes against the patched toolkit. Not tested: any game run with these patches alone, Windows.
- **Training readout (ENHANCEMENT, display only, on in Training, `TRAINING_READOUT=0` off).** In a Training fight, two lines top right in the game's menu font on the port overlay: the last hit's damage (the game's requested damage at @0x00085B84, before the leave-1-health cap), the combo's hit count (the game's combo number, gauge class `0x00879DA0` +0x3F0) and total, and both fighters' health and Stamina; it writes nothing to the game and never shows outside Training, with the pause menu up, with Hide HUD on or in Turn-based (`jsp_train_readout.h`, glue in `jsp_game.cpp`). A new combo that starts while the old combo number still shows is split off by the game's own count. The readout yields the shared overlay layer to the Port Settings page, version line and pad-join prompt, and to the rollback message line and status badges (`jsp_net_overlay_held`). Under rollback (`JSP_ROLLBACK=1`, also its local bench, which can run a Training fight) each hit is counted once: ticks the rollback core runs again (`jsp_stepper_in_replay`, a new accessor for its replay flag) do not feed the readout. Tested: host test `installer/tools/train_readout_test.sh` (also a re-run that does not count twice and the layer yielded) and the port syntax check with MinGW GCC. Not tested: a build, a game run; the placement, the game's count on a new combo inside a shown number and the P1/P2 order wait for a Training run.
- **Mods folder: a `roster` section in `mod.json` (ENHANCEMENT, opt-in, US 1.00 only).** A mod that declares interface `roster` 1 can add fighter ids 19, 20 or 21 to the character select, behind a given id, with an optional intro-logo alias and an owned flag, with no rebuild (`jsp_roster.cpp` puts it into the guest; the pure rules, list and digest are in `jsp_mods_core.h`). The list is capped at 56 ids (the random select's stack buffer; the three allowed ids make 55). A roster mod runs only on BLUS31519 and must name it in `game.title_ids` (the EU build is unverified); an id already in the list or out of range, an `after` that names nothing, or a `logo_as` that is not a stock fighter id (on the stock list, below 200) refuses the whole mod. A roster mod is gameplay: its fighters are part of the digest, so online refuses mismatched sets. The guest side checks every expected byte first (both list pointers, the whole 52-id stock list and its terminator, the code the logo alias relies on, the free memory for the copy); on any mismatch, or if the copy is later found changed, the list pointers go back to the stock list, nothing further is hooked and the set is reported as not run as listed. The list-repoint approach was first shown by a community mod. **A fight with an added fighter is untested, and this change serves no model, voice or card art for one: do not pick an added fighter unless its full data is in place (`owned` defaults to true, so its card is selectable).** Tested: host test `installer/tools/mods_overlay_test.sh` (278 checks; 347 with the toolkit glue), the port syntax check, and one Proton run with a roster mod without assets (the list of 53 ids was written at 0x0086FE00, the owned bit stamped, the select shows a placeholder card and the page counter 01/08 instead of 01/07). Not tested: a fighter with real assets, selecting an added fighter or starting a fight with one, JSP_UNLOCK_ALL together with a roster (the shared save-update hook is compiled and host-checked only), the EU build, a Windows run.

- Drawing costs less CPU in busy scenes: the vertex shader lookup is remembered while the vertex program is unchanged (`VS_MEMO=0` turns it off, toolkit patch 2909), the fragment program's hash, size and texture units are worked out once per program and frame (`FP_FRAME_MEMO=0`, patch 2910), and the off-screen target lookup answers from a small cache while the target table is unchanged (`OFFRT_CACHE=0`, patch 2911). New diagnostics, off by default: `HITCH=<ms>` prints where the time went for a present slower than that (patch 2905) and `GPU_TIME=1` logs the costliest render-target passes (patch 2906); `GPU_OVERLAP=1` (patch 2907, off by default) lets the CPU build the next frame while the graphics card draws.
- Busy fights no longer fall from 30 to about 20 frames per second. The draw list holds 8192 draws instead of 4096: a 2 against 2 fight with the town in view has about 4,200 to 7,000 draws a frame, so every such frame was cut into two batches and the second waited for the graphics card to finish the first (toolkit patch 2913). The frame clock now lets a flip that became ready just after its 30 frames-per-second slot finish at once and brings the next vblank 2.5 ms later instead of a full 60 Hz period, and no flip completes sooner than 33.3 ms after the previous one, so nothing runs above 30 (`LATE_FLIP=0` turns it off, `LATE_VBLANK_MS` sets the delay; toolkit patch 6011 and the port's `main.cpp`). Measured on one Windows machine: the title demo 28.3 -> 29.65 flips per second, a 2 against 2 on Hidden Leaf at 4K about 22 -> 28.
- Training: the Yes/No box of Restart asks "Fight the battle from the beginning?" again (the Hide HUD row had borrowed its title text slot), and the dummy's health refills 1.5 s after it stands up again, not 1.5 s after the last hit while it is still on the ground. The test auto-pilot (`AUTO_MENU=title`, `AUTO_FB`) recovers when a menu step does not move on; these are test-only switches and off in normal play.
- Setup: when RPCS3 lists the game as a single disc image (.iso file), the locate helper recognises it (`is_iso`) instead of refusing it as "not a folder", never searches it for an EBOOT.elf, and the wizard says plainly that setup needs an extracted disc folder (the disc folder page stays empty); setup has no ISO reader (`rpcs3_locate.py`, `rpcs3_wizard.py`).
- Version line on the main menu: it is drawn only on the idle Main Menu (flow state 4, menu mode 0) and hides when the menu starts to leave, and it is smaller (scale 0.65) and placed inside the button bar, clear of the bar's slanted right end (`jsp_version_line.h`, `jsp_port_menu.cpp`; host test `installer/tools/version_line_test.sh`).
- Installer: `assemble_payload.py --tree legacy` (and `v15`) no longer builds the earlier v0.15 tree and exits with a pointer to the git tag `legacy-v15` (issue #152); `firstrun.py` builds only the current tree and stops with an error when `tree.txt` is missing or unknown; CI no longer builds or tests the legacy tree (the `toolkit` job and the legacy patch series check are gone, the `tree` input of `installer.yml` too).
- Repository layout: `Play J-Stars.bat` and `Test Fight.bat` (legacy v0.15 tree only) moved from the root into `jstars/`, next to `play.ps1` which they start; the installer never shipped them.
- Port Settings page and the main-menu version line at a resolution above 720p (`RES_SCALE` above 1, for example 4K): the overlay layer (toolkit patch 2517) set its viewport and scissor to the game's 1280x720 size instead of the back buffer's size, so both were drawn into the top-left corner of the picture. They now cover the whole back buffer.
- Repository layout: `jstars-notes/` is now `docs/archive/jstars-notes/`, `toolkit/` and `tools/toolkit/apply_toolkit.py` are now in `jstars/toolkit/`, and `docs/README.md` lists the documentation by audience. `docs/LAYOUT.md` marks every root folder current or legacy. No files deleted; the installer, CI and the checks use the new paths.
- Releases: `.recomp.json` now names the current version (`"x-version"`), which `tools/release.py bump` rewrites and `--check` (CI) compares with `installer/VERSION`; from 1.0.0 on the bump also sets its status to `released`. Its notes no longer say that nothing has been released.
- CI: both patch series are applied to scratch copies of the pinned ps3recomp, the current port's sources are compiled (syntax only, no game data) with the installer's llvm-mingw, and every host test runs from one list (`tools/ci/host-tests.txt`), also on Windows; `portable_selftest.py` is repaired for the current `firstrun.py`.
- Settings window (`jsp-settings.exe`): Start Game, its "already running" check and the Controls page's key-support notice looked for `game\JStarsRecomp.exe`, but a current-tree install places `game\jsp.exe`, so Start Game answered "The game is not built yet" and the Controls page said the game does not read key changes. The window now takes the exe name from `paths.txt` (`EXE=`), and falls back to `jsp.exe` when that file is there.
- Sound no longer stays off for the rest of the run when Windows takes the audio device away (for example a default-device change, a headset or another program, or after alt-tab): the port opens the current default device again within about a second, and it also follows a switch of the default output device while playing (toolkit patch 3004). The log shows `audio device lost` and `audio device re-opened` lines.

First pre-release. J-Stars Victory VS+ for Windows: the game is built on your PC (ps3recomp, Direct3D 12) from your own copy of the disc, no game
files are included. On the Windows PC it was tested on, it boots, plays the menus and fights with sound at about 30 frames

It is a pre-release with known problems and fewer tests than it needs:
see [issue #9](https://github.com/Tsamiuy/jsp-vs-ex/issues/9). `docs/FEATURES.md` lists each feature with how it was tested.

### For players

This is the first pre-release: it works, but it has known problems and has been tried on few PCs. You need your own copy of the game (disc image or disc folder); no game files are included. Your PC needs a 64-bit processor with AVX2.

**New**

- **The installer:** `jsp-setup.exe` (or the portable zip) builds the game on your PC from your own copy of the disc, and a launcher starts it. On the PC it was tested on, it reaches the menus and plays fights with sound at about 30 frames per second.
- **Picture:** higher resolutions, a resizable window, borderless fullscreen, and "EX" in the title logo.
- **Controls:** play with the keyboard, the keyboard and mouse, or a controller, each with its own button layout. A second player can use the keyboard or a second controller.
- **Options:** a setting for the size of the fight HUD (the bars and icons during a fight), an Exit Game entry in the Options menu, a Hide HUD row in Training Mode, and an FPS counter.

**Changed**

- Setup checks that your game's main file (the EBOOT) is the known version 1.00 and refuses the other region's.
- Fight intros no longer show half-drawn characters, and new objects or camera turns no longer freeze the game for a moment.
- Importing a save from RPCS3 is safer: your old save is kept if the import fails.

### What you get

- A Windows installer (`jsp-setup.exe`) and a portable zip that do that build, and a launcher to start the game.
- Higher resolutions, a resizable window and borderless fullscreen, and EX in the title logo.

### Changes since the first builds

- Installer and CI: the port on ps3recomp v0.19.0 (`installer/port`) is now the default tree of
