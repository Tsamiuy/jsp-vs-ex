# LOD baseline lifetime hooks

The US 1.00 lift can now invalidate cached LOD originals when the title initializes or destroys the tracked object. This prevents a fresh value at a reused guest address from being mistaken for a previous hook output merely because its bits coincide. The change does not create an application receipt, session agreement or battle-start gate.

The `0x70`-byte object is separately allocated; its owner stores a pointer at `+0x80C`. For the supported program, base initialization `0x003955B4` resets all tracked threshold/flag fields and is reached by derived initializers `0x00395788/0x003957D8`. The common base destruction entry `0x0039595C` is reached by the target class's deleting and non-deleting destruction routes. Both entry callbacks erase the old ledger key without reading guest memory. Initialization is evidence that tracked originals are being reset, not proof of allocator identity or exclusive ownership. Stage properties are written after constructor return, so the next eligible select captures their final values rather than capturing constructor defaults.

Toolkit patch6014 wraps the original named entries around private lifted bodies. Named direct calls, dispatch-table entries and trampoline targets continue to name the wrapper. The actual select entry `0x003959C8` therefore applies the reader once on either direct or indirect paths. Its old indirect-call handling is skipped only after both emitted-hook verification and binding to the actual loaded program; vanilla/manual or unsupported lifts retain their previous indirect reader behavior. Callbacks preserve guest registers and the existing typed return behavior.

The manifest restricts this capability to US 1.00 program SHA256 `a8a1543b914b70aa87a83e50c6d90c216d9ed1b60c49c629ddad5590874d7716` or loadable-segment SHA256 `eb43c5d6ebabba67c037bbf49159ef7e1e4f19eba083c1269e603a7f3520488e`. Region selection alone never enables it, including `--allow-unknown-eboot`. EU, updates and unknown programs have no verified entry-hook capability.

`firstrun.py` fingerprints the manifest, verifier, input image, lift recipe and toolkit, and records hashes of all generated PPU sources after a successful lift. Cache reuse verifies those outputs. CMake verifies the actual input and emitted wrappers at configure time and before every build, then writes its private capability header. Missing, partial, changed or stale output fails verification and revokes the header. A compile flag alone does not enable the feature. Manual vanilla lifts without an input receipt remain disabled. Moving a complete payload preserves relative receipt filenames; the existing installer resets the compile tree at its new location.

Patch6016 exposes the loader's actual owned file buffer to an optional title guard before PT_LOAD guest-memory writes. Main installs the guard before calling the loader. Every load attempt first revokes earlier activation and clears the ledger without reading guest objects, including failed opens and malformed headers. A verified build hashes that actual buffer with SHA-256 and checks the supported whole/segment identity; mismatch rejects the load before guest writes. It does not separately reopen the pathname. Disabled builds preserve the loader's prior acceptance behavior while leaving the new entry callbacks inactive. SHA-256 runs only during image binding, not in the object hooks. A successful binding is still not evidence that all required graphics consumers have applied a host setting.

The lifter checks expected final function ends and refuses tail/fallthrough bodies or emitted interior entries. The verifier separately checks the three exact range markers, unique wrappers, private-body references, dispatch entries and absence of a tail continuation. These checks are deliberately bounded to the selected entries. A generic function wrapper does not intercept a separately emitted interior guest entry.

One mutex orders all ledger access, cached MD/OD/generation state, initialization/destruction erasure and complete generation sweeps. After verified normal restoration and ledger discard, an atomic generation marker allows unchanged normal selects to return without reading guest objects or taking the mutex. A new generation takes the synchronized path. This has no measured performance claim.

The mutex protects host bookkeeping and retirement ordering. It does not synchronize unrelated engine writes or prove that stage property publication cannot overlap selection. Generic memcpy/copy loops, relocation and copies of already scaled source objects can bypass constructors; their semantics remain unproved. Full required-object reachability, thread ownership, safe points, runtime teardown/reinit, real-title behavior, Windows and network acceptance remain open. Do not turn a settings snapshot or this build capability into an effect ACK.

Validation commands (Nix shell; native checks require the shared build lock):

- `python3 installer/tools/export_toolkit.py --out <scratch-sdk> --repo <local-sdk-repo> --no-fetch`
- `python3 installer/tools/lod_hooks_test.py --lifter <scratch-sdk>/tools/ppu_lifter.py` exercises actual patched lifter output using authored synthetic PPC, including missing/range/tail/interior/config/tool/image/output refusal. `--native` compiles that synthetic emission and checks direct, emitted-table and trampoline callback ordering.
- `python3 installer/tools/lod_lifetime_test.py --mutations` extracts the actual authored callbacks/reader and links the real settings store against a fake VM. It isolates numeric coincidence, original flag1/MAX output0/fresh flag0, destructor retirement, unchanged-normal no-access, register preservation, verified/legacy exact-once wiring, and host-map contention. Its fake engine writer uses the same test lock; this is not a title publication proof.
- `python3 installer/tools/lod_image_guard_test.py --loader <scratch-sdk>/runtime/ppu/ppu_loader.cpp` checks the actual binder's full and segment identities, changed/malformed input, disabled behavior and revocation, compares SHA-256 with hashlib over boundary lengths through 1 MB, and compiles the authored SDK loader through PT_LOAD copying. Guard/removal mutants must fail the reject-before-write and failed-open-revocation controls. Optional platform diagnostic threads after the copy phase are excluded.
- `python3 installer/tools/session_reader_effects_test.py --mutations` retains the existing reader/restoration controls.
- `python3 installer/tools/firstrun_selftest.py --units` checks installer fingerprints and moved-folder behavior with mocked build steps; actual emitted-output verification is covered by the lifter suite.

Native integration results and independent review must accompany the exact local candidate. No title executable or live session result is established by these source and synthetic checks.
